# Sale Alert Project Audit

**Audit date:** 2026-11-07  
**Scope:** Existing Android app sources, Gradle configuration, manifest, Firebase client usage, native sources, resources, and the companion Python/Flet script. This report describes the supplied baseline and records the Phase 2 remediation status.

The project has no Git metadata, so its original commit and any deployment-side configuration could not be inspected. A private pre-change source/configuration backup was created outside the project workspace.

## Phase 2 validation

- Baseline `:app:assembleDebug` succeeded before changes.
- After Phase 2, `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:assembleDebugAndroidTest`, and `:app:assembleRelease` succeeded. The instrumentation APK compiled but was not run on a device.
- The new unit test suite initially exposed use of Android's mocked `Uri` API in local JVM tests. URL parsing was changed to `java.net.URI`, and the rerun passed.

## Phase 3 — Offline Room cache and static feed foundation

- Added indexed `DealEntity` and sync metadata tables, a singleton Room database, and a repository that exposes local Flow queries with search, category, city, source, expiry, and paging parameters.
- Replaced screen/category Firestore reads and unmanaged snapshot listeners with debounced Room-backed feed queries. The Firebase SDKs and Google Services plugin, which had no remaining safe app call sites after merchant publishing was disabled, were removed from the Android build. The existing Firebase configuration file was preserved.
- Added a WorkManager sync worker with connected-network constraints, a 24-hour unique periodic schedule, manual one-time refresh, exponential retry, HTTPS/same-host relative pack URL validation, bounded downloads/decompression, SHA-256 verification, deal validation, and transactional pack replacement. Failed downloads or invalid packs leave existing cached data intact.
- Configure the public CDN base URL through the Gradle property `dealsCdnBaseUrl` (for example, in the developer's user-level Gradle properties file, not in app code). The CDN should publish `/manifest.json`; each manifest pack points to a relative `.json.gz` file, declares the compressed file's exact `sizeBytes` and lowercase or uppercase SHA-256 checksum, and carries a monotonically increasing pack version. Each decompressed pack is JSON with `schemaVersion: 1` and a `deals` array. Deal timestamps may be UTC ISO-8601 strings or Unix milliseconds. Publish all pack objects first and the manifest last. The feed must contain only approved, sourced deals; no sample promotions are included.
- No CDN endpoint or approved feed is configured in this workspace. Therefore sync is intentionally not scheduled and the local feed remains empty until the owner configures a provider and publishes real data.
- Initial KSP processing exposed a Room 2.6.1/KSP signature incompatibility in this project's Kotlin toolchain. Room was upgraded to 2.8.5, after which symbol processing succeeded. A Kotlin extension-reference issue in the repository mapper was also corrected.
